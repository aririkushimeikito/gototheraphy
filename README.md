# Gototherapy — website and membership-platform frontend

A premium, static, framework-free frontend for [gototherapy.co.uk](https://gototherapy.co.uk/): a UK directory of therapists, supervisors, coaches and trainers whose registration, insurance and supervision are checked by a person.

Built from two source documents, which remain authoritative:

- `gototherapy-design-system.pdf` — Design System v2.0 "Stone & Ember" (palette, type, components, voice, verification model, page priorities, SEO patterns)
- `SEO-Pages.pdf` — Yoast SEO details (titles, descriptions, focus keyphrases, noindex rules, the slug inconsistency)

Everything is HTML5, CSS3 and vanilla JavaScript modules. No frameworks, no build dependency at runtime. A small Python helper (`tools/build.py`, standard library only) generates the directory pages from data and keeps the shared header/footer in sync.

---

## Running it

The site must be served over HTTP (ES modules and `fetch` do not work from `file://`).

```bash
python3 -m http.server 8000
# open http://localhost:8000/
```

Any static host works: GitHub Pages, Netlify, Cloudflare Pages, nginx, Apache. Links are document-relative, so the site works at the domain root **and** under a sub-path such as `https://<user>.github.io/gototheraphy/`.

After editing any page, partial or data file, run:

```bash
python3 tools/build.py
```

This regenerates the directory pages, re-injects header/footer, rewrites links and rebuilds `sitemap.xml`. It is idempotent.

## Changing things

### Content
- **Static pages**: edit the HTML in the page folder. Keep one `<h1>`, the direct-answer paragraph (`.answer`) near the top, and the `<title>`/description in the head. Run the build afterwards.
- **Header / footer / head links**: edit `tools/partials/*.html` once, run the build. Every page carries `<!-- @chrome:header -->…<!-- /@chrome:header -->` markers that the build fills.
- **Stories**: write a new folder under `/stories/<slug>/index.html` (copy an existing one), then add its entry to `data/articles.json`.
- **Towns and issues**: edit `data/locations.json` / `data/issues.json`. Long-form copy goes in `longform`; issue pages also need `clinicalReviewer`. Pages without both stay `noindex` automatically.
- **Demo profiles**: `data/therapists.json`. Every record is fictional and flagged `demo: true`; demo records never count towards indexing thresholds. Remove them before launch.
- **Placeholders**: anything wrapped in `.placeholder` or marked `CONTENT REQUIRED — DO NOT PUBLISH` must be replaced before the page is indexed. Search the repo for `Content required`.

### Colours
All colour tokens live in `assets/css/variables.css`. The palette is the design system's "Stone & Ember" set. Rules that must survive any change: `--clay` is a fill colour only (text uses `--clay-ink`), `--sky` is never used for text, and Ember appears at most three times per screen.

### Typography
Two families only: Instrument Serif (display) and Schibsted Grotesk (UI/body), loaded from Google Fonts in `tools/partials/head.html`. The scale is in `variables.css` (`--fs-hero`, `--fs-h2`, `--fs-h3`, `--fs-lead`, `--fs-body`). To self-host, drop the font files in `assets/fonts/` and replace the Google Fonts link with `@font-face` rules in `base.css`.

### Images
Supplied images were reviewed against the design system's photography rules (natural light, real interiors, space around the subject, no clinical stock, never a stock face on a profile). Fourteen were placed; the clinical set (stethoscopes, white coats, "medical service" props) was not, because the design system explicitly moved away from that aesthetic. Every original is kept as WebP in `assets/images/library/` (`set1-01` … `set3-08`).

### Logo
A temporary wordmark ("goto**therapy**" in Instrument Serif, with a small `temp logo` tag) is used until the final logo is supplied. Replace `.brand__mark` in `tools/partials/header.html` and `footer.html`, and `assets/icons/logo.svg`, `favicon.svg`, `apple-touch-icon.png`.

### Operating hours
`assets/js/hours.js` holds one configuration object (`SUPPORT_HOURS`) with weekly hours, special hours and closures, plus an engine that computes "Open now / Closed now / Opens at / Closes at" in the Europe/London zone every minute. The same engine renders each member's practice hours from their availability. The support hours are marked as placeholder and must be confirmed before publish.

## Connecting a backend

See `BACKEND-INTEGRATION.md` for the full contract. In short:

- **Therapist data**: replace the fetch targets in `assets/js/data.js` (one file). Everything else reads through it.
- **Authentication**: `/login/` posts to `POST /api/auth/login`; the account reads `GET /api/me`. Sessions are httpOnly cookies. Nothing is stored in the browser.
- **Stripe**: Checkout and Billing Portal sessions are created server-side; the frontend only redirects and reads subscription status. Only `STRIPE_PUBLISHABLE_KEY` may ever appear in frontend code, and it is not needed for Checkout redirects.
- **Booking**: `assets/js/booking.js` documents the four endpoints; calendar sync (Google, Microsoft 365, Calendly-style) sits behind them.
- **Email**: transactional emails (application received, checks complete, session request, expiry warning, payment failed) are triggered server-side.
- **Verification workflow**: the admin/verification UI states, per-role check rules and the annual recheck model are described in `BACKEND-INTEGRATION.md`; the role rules themselves are in `data/roles.json`.

## Quality checks performed

- Every page: one `<h1>`, unique title and description, canonical, Open Graph, Twitter, JSON-LD, robots directive.
- Responsive: no horizontal overflow at 320, 375, 390, 414, 768, 1024, 1280, 1440, 1920 on the homepage, search, profile, join, account, pricing and article pages (Playwright).
- Interactions tested headlessly: mobile menu (open, Escape, aria-expanded), search filters and URL sync, empty state, booking request flow, join validation and step navigation, account billing states.
- Accessibility: skip link, visible focus, labels on every control, error summaries, `aria-live` regions, dialog focus return, 44px targets, reduced-motion support, content visible without JavaScript.
- No `!important`, no bare-element styling beyond the base reset, no third typeface, no review or rating fields, no invented prices, counts, professionals or outcomes.

## Deployment

**Static web host (cPanel, LiteSpeed, Apache, nginx).** Upload the repository contents to the document root (or point the host's Git deployment at the branch). `.htaccess` provides the 301 redirects, the custom 404, https/non-www enforcement, caching and compression; nginx equivalents are in `SEO-IMPLEMENTATION.md`. Nothing needs to be built on the server: run `python3 tools/build.py` before you commit, and the built pages are what gets deployed.

**GitHub Pages.** 
The repository is set up for GitHub Pages from `main` (root). `.nojekyll` disables Jekyll processing. GitHub Pages cannot serve 301 redirects, so `/articles/` is a meta-refresh stub with a canonical to `/stories/`; on a host that supports rules, use `_redirects` (Netlify/Cloudflare) or the Apache/nginx snippets in `SEO-IMPLEMENTATION.md`.
